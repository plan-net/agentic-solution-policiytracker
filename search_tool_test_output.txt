## Key Findings

### Critical Issues
1. **No Source Attribution** - All searches returned "0 sources"
   - Source extraction logic is running but not finding any sources
   - No [Source: ...] annotations in results
   - This is a major UX problem - users don't know where info comes from

2. **No Relevance Scores** - Results have sequential numbering but no confidence scores
   - Can't distinguish high-confidence from low-confidence results
   - Can't filter by quality threshold

3. **Relationship-Focused Search Broken** - Requires center_node_uuid parameter
   - Error: "No center node provided for Node Distance reranker"
   - This search type is non-functional

4. **Result Quality Issues** - Later results become increasingly off-topic
   - Example: Cava Group restaurant chain in results for Google regulatory query
   - Example: Zscaler mentioned without relevance to query

### Source Extraction Problems
Looking at the code (lines 135-343 in search.py), the source extraction has 5 fallback methods but ALL are failing:
- Method 1: `_extract_source_info()` → gets episode, tries to parse YAML frontmatter
- Method 2-5: Various parsing fallbacks for filename, episode name, URLs

**Why it's failing**:
- Episodes may not have YAML frontmatter
- Episode bodies may not be accessible via `get_nodes_and_edges_by_episode()`
- Filenames don't match expected patterns
- Result is: complex extraction logic that doesn't work in practice

### Output Format
Current format is markdown text only:
```
Found 18 facts for 'query' (showing top 5):

1. Fact text here (Relationship: TYPE)
2. Fact text here (Entity: NAME)

... and 13 more results available.
```

**Missing**:
- Relevance scores
- Source URLs
- Structured data (JSON)
- Entity extraction from facts
- Metadata (timestamps, creation dates)
